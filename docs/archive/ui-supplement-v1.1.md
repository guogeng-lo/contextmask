# ContextMask 介面調整規格補充

日期：2026-10-10  
依據：作者操作 v1.0 後的回饋、設計決策 D02 與信任提示討論 D03。  
狀態：介面方向與未完成敏感欄位的複製政策已確認；實作與操作驗收尚未完成。

> 說明（整理v1.1時加註）：這份是做v1.1之前整理的介面需求，內容沒有改，所以上面的「狀態」是當時的情況。這些需求已經做進v1.1，整理在《ContextMask規格書v1.3》的F13、F14和第八節；我自己的操作驗收見規格書第十一節的A41和A48。

## 調整原因與採用方案

我覺得能自己決定要遮哪些內容這點不錯，不過介面有點雜，提示可能漏看，尤其是為什麼從 USER_2 開始、還原為什麼有些沒換這些地方。雖然使用者可能有資工相關知識，我還是希望門檻低一點。

所以目前我比較偏向保留原文跟結果對照，細節可以收起來，需要的時候再看。操作不要太麻煩，畫面也不用大改，先把提示位置、間距跟按鈕整理一下，讓人更快上手理解。

本補充調整資訊呈現與操作負擔，沿用既有遮罩、映射與檢查規則。

下面的規則是 AI 根據這次討論整理的。漏遮本身還是要修，提醒不能代替修正；一般正常流程也不要因此多出一堆確認。

## 介面要求

| 編號 | 要求 |
| --- | --- |
| UI01 | 桌面保留原文與遮罩結果對照；目前操作步驟與主要操作按鈕容易辨識。手機依既有流程單欄呈現。 |
| UI02 | 原文既有代號會造成跳號時，在遮罩結果附近直接顯示原因，不要求返回審查清單或展開詳細說明。提示須依實際分配結果產生。 |
| UI03 | 還原結果附近直接顯示摘要：已還原的次數、原文既有代號的保留情況，以及需要確認的未知或疑似被修改代號。不得將不同情況統稱為還原失敗。 |
| UI04 | 詳細偵測理由、一般說明及通過的檢查細節可展開查看；每筆候選仍能查看種類、理由、可信度或風險，並選擇遮罩或保留。 |
| UI05 | 需人工處理、無法還原或導致複製停用的問題直接顯示在相關操作附近，不以預設收合的內容承載唯一提醒。狀態同時使用文字，避免只靠顏色。 |
| UI06 | 一般成功狀態以畫面內摘要呈現，不新增強制彈窗、額外切頁或重複確認。清除資料等既有確認依原規格處理。 |
| UI07 | 精簡畫面不取消可逆性、JSON 有效性等既有阻擋條件。檢查通過的摘要僅描述檢查範圍，不使用「完全安全」或「沒有敏感資訊」等結論。 |
| UI08 | 複製按鈕附近的摘要區分已完成的遮罩與檢查、仍需處理的項目。已知問題提供位置及處理方式；不得以格式或可逆檢查通過掩蓋未完成的敏感欄位處理。 |
| UI09 | 已辨識敏感欄位卻未完整處理時，直接列出問題與風險；使用者明確確認後仍可複製。確認不得預先選取，僅適用於當次產生的結果。其他既有硬性阻擋仍有效。 |

## 未完整處理的敏感欄位與複製

作者在 D03 選擇「醒目提示風險，使用者確認後仍可複製」。此流程僅處理工具已辨識但無法完整處理的敏感欄位，不能代替修正已確認的漏遮問題。

1. 複製區直接顯示未完成項目的欄位、位置與可能外露的風險，提供修改原文或補充自訂遮罩的處理方向。
2. 仍有這類未完成項目時，使用者須明確確認「本次內容仍有未完整遮罩的敏感項目，我已查看並決定繼續複製」，才可複製。確認元件預設未選取。
3. 確認後風險提示保持可見；不得將本次結果標示為敏感資訊均已遮罩。
4. 修改原文、自訂文字或審查選項，或重新掃描、重新產生結果後，舊確認立即失效。確認狀態不寫入儲存體。
5. 可逆性、有效 JSON 輸出檢查失敗或其他既有硬性阻擋，無法以此確認越過。沒有這類待確認項目的正常流程，不新增確認動作。

本次參考資訊分組與主次層次；ContextMask 的提示文字、逐筆審查與還原流程依本專案規格設計。未複製或匯入參考工具的程式碼。這些頁面的排列方式是否適合 ContextMask，仍須由作者操作新版後評估。

## 操作驗收

以下項目於實作後逐項確認，目前均未驗收。

- [ ] 使用原文既有 `USER_1` 的虛構案例，產生 `USER_2` 後，可以在遮罩結果附近看到具體原因，無須展開細節。
- [ ] 同一批虛構回覆含本次已知、原文既有及未知代號時，還原摘要能分別解釋處理情況，未知項保持可見。
- [ ] 將一般細節收合後，仍可完成掃描、逐筆審查、產生、複製與還原；需要時可展開每筆判斷依據。
- [ ] 阻擋複製或需要人工確認的案例，其問題與下一步處理方式可直接看見。
- [ ] 桌面與手機操作時，重要提示出現在相關結果或操作附近；一般流程不增加強制確認步驟。
- [ ] 未完整處理的敏感欄位案例，複製附近明確顯示問題；畫面不會只呈現檢查通過的狀態，且執行作者最終決定的複製政策。
- [ ] 仍有未完整處理的敏感欄位時，未確認前不能複製；明確確認後可以複製，風險提示仍可見。
- [ ] 確認後修改原文、自訂文字或審查選項，或重新掃描、重新產生結果，均要求對新結果重新確認。
- [ ] 可逆性或有效 JSON 輸出檢查失敗的案例，即使確認敏感欄位風險，仍不能複製。
- [ ] 作者親自操作新版後，說明跳號與還原結果是否更容易理解，以及是否出現新的操作負擔；記錄具體觀察，不能僅憑程式測試通過判定介面改善。
