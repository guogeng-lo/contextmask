# ContextMask修改紀錄（v1.0→v1.1）

2026-10-11

## 為什麼有這一版

v1.0做出來之後，我先自己用虛構的例子操作了一輪，另外也請Codex做了一次測試審查。

我自己用的感覺是：可以自己決定哪些要遮，這點不錯，但畫面有點雜，有些提示很容易漏看。像我貼的例子裡原本就有USER_1，路徑就變成用USER_2，雖然審查清單那邊有寫原因，但不仔細看還是不知道為什麼從2開始。還原那邊也是一樣的感覺，為什麼有些代號沒換，不容易一眼看出來。

Codex那邊則測出幾個真的會漏遮的地方（R01～R04），還有測試程式寫死了某台電腦的瀏覽器路徑、CSP的說明不夠精確（R05、R06）。原始的審查內容在《TEST-REVIEW-v1.0》。

所以這一版我定的重點是：先把漏遮修掉，再處理提示看不到的問題；介面不用整個重做，保留原文跟結果的對照，小修排版、把細節收起來就好。這一版的改動，我都是從使用者會不會漏看、會不會覺得麻煩這個角度去決定的（就是規格書第二節寫的「把使用者當成什麼都不會的人來設計」）。

## 我這次做的決定

詳細的考量在《設計決策紀錄》，這裡只寫結論：

- D01代號：維持USER_1這種短代號、遇到原文已有的就跳號。這次只是把跳號的原因直接寫在結果旁邊。
- D02介面：保留原文和結果對照，細節收起來，提示放在相關的按鈕旁邊。也有想過改成一步一步引導的方式，但我覺得操作會變麻煩。
- D03沒遮完整的敏感欄位：AI原本比較建議直接擋下複製，我選的是醒目提醒，使用者確認之後還是可以複製。確認只算這一次的結果，內容改了就要重新確認。至於還原不回來、原本有效的JSON被弄壞這種，還是一樣擋下，確認也不能跳過。
- D04敏感欄位底下的物件：這是操作回饋和AI測試審查之後決定的，寫在最後面。

## 修掉的漏遮

| 編號 | v1.0的問題 | v1.1的結果 |
| --- | --- | --- |
| R01 | `{"password":`換行再寫`"SYNTHETIC_SECRET_ABC"}`，密碼值在下一行就找不到，畫面卻顯示檢查通過 | 值寫在下一行也會遮。JSON、JavaScript、YAML的下一行寫法都處理；下一行是別的欄位或巢狀物件時不會亂遮 |
| R02 | YAML的`'demo''SYNTHETIC_SECRET_SUFFIX'`只遮到`demo`；`password: \|`底下每行結尾的`,;`留在外面 | `''`當成同一個字串，整段遮完；多行值行尾的逗號、分號一起遮。順便處理`>-`、`\|2`、`!vault \|`和延續到下一行的值 |
| R03 | Python的`password = """SYNTHETIC_SECRET_ABC"""`完全沒被抓到 | 三引號同一行完整遮；跨行的每一行分開遮，縮排不動；找不到結尾或超過200行時只遮第一行，並列為沒遮完整、要確認才能複製 |
| R04 | 原文只有`123456`或`true`時，換成代號後就不是JSON了，卻沒有檢查 | JSON檢查改成只要原文能被解析就做，物件、陣列、字串、數字、true／false、null都算；遮罩後解析不了就擋下複製 |

修的時候也一起補了幾個同類型的寫法：跨行的反引號字串、`"abc" + "def"`這種接在一起的字串、Python拆長字串用的括號寫法、記錄檔裡字串包著的JSON（`"{\"password\": \"abc\"}"`）、`print("password:" "abc")`這種欄位名稱在字串裡的情況。陣列沒有結尾、或陣列裡夾著物件時，v1.0會整個略過，現在會遮找得到的項目，沒有結尾的也會列為沒遮完整。

## 另外一輪漏遮審查

R01～R04改完之後，我要Claude再做一輪漏遮審查，拿更多種寫法和特殊字元去試，結果又找到一些會漏遮或誤遮的地方，這次一起修掉：

- 型別標註和中括號：`def connect(password: str = "…")`，v1.0把`str`當成值（型別名稱本來就不遮），後面真正的密碼就漏掉了；`config["password"] = "…"`和Go的`var password string = "…"`也是整個沒抓到。
- 讀設定、寫設定時寫在程式裡的值：`os.getenv("DB_PASSWORD", "…")`、`process.env.TOKEN || "…"`、PHP的`define('DB_PASSWORD', '…')`、Java的`setProperty("password", "…")`。
- 格式化字串：`log("password=%s", "…")`，v1.0遮到的是`%s`這個佔位，真正的參數反而留著。現在會遮對應的參數，同一個字串有好幾個佔位也對得到。
- 和寫死的字串比對：`if password == "…"`，作業程式裡滿常見的。
- 命令列和設定檔：`docker run -e DB_PASSWORD=abc,def`這種值裡有逗號的（v1.0只遮到逗號前面）、值本身以`=`或`>`開頭、`a\ b`這種跳脫的空白、`{SSHA}…`這種大括號開頭的值、INI裡有空白的值；`passwords`、`api_keys`這種複數的欄位名稱、Rails的`secret_key_base`，以及從表格轉出來、名稱後面多一個空白的`"Password "`。
- 原本會誤遮的：`const token = getToken(user)`這種程式呼叫，v1.0會把`getToken(user`遮成一個代號，程式反而看不懂；現在呼叫本身不遮，括號裡的欄位照常檢查。

另外像`PGPASSWORD=abc psql -h db`，空白後面可能是要執行的命令，也可能是`.env`裡沒加引號、本來就有空白的密碼，工具看不出來。這種照D03的規則處理：遮到空白為止，後面那段列為要確認。

還是認不出來的也寫進規格書6.2了，例如`secrets:`底下的`db: abc`，因為`db`不是敏感字，不會自動遮。這個後來我決定用D04處理，見最後面。

## 新增：沒遮完整時要確認（D03）

工具認出是敏感內容、但沒辦法完整遮住時（例如找不到結尾引號、看不出路徑裡使用者名稱到哪裡為止），會在「複製給AI」上方列出：

- 第幾行、什麼問題
- 風險：哪些內容會原樣送出
- 可以怎麼處理：例如把完整名稱加進自訂文字後重新掃描

這時候複製按鈕先停用，下面有一個預設沒勾的確認框：「本次內容仍有未完整遮罩的敏感項目，我已查看並決定繼續複製」。勾了才能複製，提醒也不會因為勾了就消失。改原文、改自訂文字、改遮罩選擇，或重新掃描、重新產生，確認就失效。使用者如果照建議補上自訂文字，讓那些地方都被遮住，就不用再確認。

只是範圍需要看一下、但其實已經遮住的（例如連線字串格式看不懂、整段先遮起來），列成「提醒」，不影響複製。正常沒有問題的流程，畫面上不會出現確認框。

## 介面小修（D02）

這部分由我提出調整要求，主要由Claude修改程式。跳號原因和還原摘要也由Claude依照實際的分配和還原結果計算；我關心的是提示放哪裡、看不看得懂，以及操作會不會變麻煩。

- 遮罩結果下面直接寫代號為什麼跳號，例如「原文本來就有USER_1，所以使用者名稱的新代號跳過這個編號，這次用的是USER_2」。這是照實際分配算出來的；同一批裡之前分給別的內容、現在選了保留的編號，也會說明。
- 還原結果下面直接放摘要：換回幾處、哪些是原文本來就有所以沒換、哪些是不認得的或看起來被改寫的要自己確認。完整報告收起來，需要再點開。
- 複製按鈕上方分成「已經完成」和「還要處理」兩部分。通過的檢查收成一行，點開才看細節，而且寫清楚這些檢查只代表代號換得回來、格式沒被弄壞，不代表沒有其他敏感資訊。
- 每一筆偵測結果的「為什麼被偵測」和「如果保留」收進「判斷依據與保留的風險」，種類、可信度、位置和遮罩／保留按鈕還是一直看得到。
- 目前在第幾步，那個面板和步驟編號會亮起來，主要按鈕只有那一步是實心的。
- 各種狀態都用文字和符號標示（✓、✕、!、i、－），不只靠顏色。
- 頁尾的隱私說明改得更精確：網頁不會把內容傳出去，但CSP管不到擴充功能、輸入法、剪貼簿工具這些網頁以外的程式。支援哪些寫法收在頁尾可以展開的地方。
- 順便修了一個v1.0的小問題：審查清單只有一頁時，上一頁／下一頁那一列還是會出現（樣式蓋掉了隱藏的設定）。

## 開發和測試（R05、R06）

- 瀏覽器測試不再寫死某台電腦的瀏覽器路徑，預設用Playwright安裝的Chromium，需要的話可以用環境變數`CHROMIUM_PATH`指定。
- 測試程式自己開一個暫時的本機伺服器，不用另外開一個視窗跑python；開發說明裡也寫清楚要在哪個資料夾、用什麼指令，Windows的PowerShell和命令提示字元各怎麼設定。
- `build.cjs`現在直接產生根目錄的`index.html`，就是GitHub Pages要用的那個檔案。
- CSP雜湊對不上的效果實際測了一次：只改HTML文字沒影響；改了樣式沒重算，只有樣式被擋；改了程式沒重算，整段程式被擋、畫面停在「網頁程式沒有啟動」；用`tools/update-csp.cjs`重算之後恢復正常。
- 原本v1.0的核心測試都保留，而且全部通過；另外新增v1.1的測試，包括上面R01～R04的例子、另外一輪審查找到的寫法、確認流程、跳號原因、還原摘要、隨機組合測試和特殊輸入的效能測試。隨機組合測試會在密碼中間夾特殊字元，而且要整段都遮到才算通過。實際的指令、環境和結果在《TEST-REPORT-v1.1》。

## 操作回饋和AI審查之後再改的

v1.1做好之後，我負責基本操作和使用體驗回饋，另外請Codex幫忙檢查程式和找錯。Codex重跑75＋43項核心測試、隨機測試A和B各20,000組，都通過；重新建出的HTML也和交付版本一致。跳號說明、還原摘要、D03確認和重設、JSON阻擋，由Codex在畫面上確認。當時Codex沒有完整重跑42項瀏覽器測試和兩輪十萬組隨機測試。這些技術測試不算成我親自執行。

不過Codex依我的要求另外補測，又找到三類漏遮。我要求把這些問題修好再公開：

1. 呼叫的密碼參數換行就漏遮。像下面這樣完全沒遮，也沒有D03的確認提示；`setProperty`、`define`和部分格式化`log`的寫法也有同樣問題。呼叫裡的字串沒貼完整時，也可能直接被忽略。

   ```
   pw = os.getenv("DB_PASSWORD",
       "SYNTHETIC_A9")
   ```

2. YAML欄位名稱加引號之後，延續行漏遮。`"password": SYNTHETIC_A9`下一行縮排再寫`SYNTHETIC_B8`，只遮第一行，`SYNTHETIC_B8`留著，而且可以直接複製。這種多行值是YAML允許的寫法。
3. 中括號加空白就漏遮。`config["password"]`能處理，但`config[ "password" ] = "SYNTHETIC_A9"`完全沒遮，也沒有針對這筆的確認。

中括號空白、呼叫參數換行和YAML延續行的修正，主要由Claude完成。呼叫裡的字串沒貼完整時，現在會遮第一行，並列為要確認。三類問題的重現案例由Codex提供，Claude把它們加入核心、瀏覽器和隨機測試，再重跑確認。我負責要求查錯和修正，以及基本操作和使用體驗回饋。

### 操作新版的感覺（A41）

跳號說明和還原摘要有比較好懂，操作也還行，就算是入門的人應該也會用。不過「支援哪些寫法、有哪些限制」放在最下面還要點開，我自己當使用者看了一下，還真不一定會滑到下面點開來看；「查看要複製的完整內容」和其他地方也一樣，比較重要的資訊使用者不一定會點開或特別注意。我覺得要多加引導一下，讓使用者能更確定、更安心地把內容複製給AI，所以我提出以下調整，主要由AI修改畫面：

- 最上面直接寫工具找得到什麼、找不到什麼，要自己加進自訂文字的有哪些；完整清單才收起來。
- 複製按鈕上方加「送出前再看一次」，三件事直接寫出來，每一件都有按鈕可以打開完整內容、跳到自訂文字、打開完整的支援範圍。
- 選了保留的那一筆，風險直接顯示，不用展開。

這些都是直接寫在畫面上，沒有多加步驟或確認。

### D04敏感欄位底下的物件

像`secrets:`底下的`db: abc`，`db`不是敏感字，所以不會遮。我決定這版保留逐欄位遮罩，再對敏感欄位底下的物件加上D03的確認，比較符合希望保留除錯線索、操作又不要限制太多的方向：`credentials`裡可能同時有帳號、密碼和設定值，全部遮掉會少掉除錯線索；`secrets`已經是明確的風險線索，應該在畫面上提醒，不能只寫進規格的限制；這版先把提示和確認做好，範圍比較能控制，「依父層判斷所有子欄位要怎麼遮」之後再做。

所以現在`password`照原本的規則遮，`db: abc`的用途看不出來，就在複製按鈕上方醒目提示，請使用者檢查，需要遮的值可以加進自訂文字；也可以看過之後勾選確認再複製。確認一樣只算這一次的結果，內容改了就失效。提示照我寫的那句改；判斷物件範圍到哪裡、哪些子欄位已經遮到的程式比較複雜，請Claude照這個決定寫。

### 設計原則

這一輪我給自己一句話：把使用者當成什麼都不會的人來設計。重要的提示不能只放在要點開的地方，這句我也寫進規格書第二節了。

## 補充審查之後再改的

上面那些改完之後，我又請Codex審查一次交付檔。舊的三類漏遮確認修好了，但Codex補測又找到兩個D04的確認缺口，詳細的重現方式在《TEST-REVIEW-v1.1》。我要求這兩個也修好再公開：

1. R07：`secrets`底下保留純中文、純符號的字串，或是`"false"`、`"demo()"`這種字串，第2步有提醒，第3步卻沒有確認框，可以直接複製。原因是程式把不含英文字母和數字的內容、看起來像布林值或程式的內容都當成「不是值」排除掉了。我的想法是，已經有`secrets`這種風險線索，物件裡沒遮的字串就應該讓使用者確認，不能因為內容看起來像什麼就略過。現在引號裡的字串不管內容是什麼都算值；沒引號的才排除`+`這種運算子、`false`這種關鍵字和函式呼叫。

   ```json
   {
     "secrets": {
       "token": "SYNTHETIC_A9",
       "db": "虛構測試密碼"
     }
   }
   ```

2. R08：物件超過200行時，程式只看前面200行，前面都遮到了就當成整個物件處理好，後面的`SYNTHETIC_TAIL`沒遮也能直接複製。現在看到上限、物件還沒結束時，一定要確認，而且不能用自訂文字解除，因為後面根本沒檢查。審查報告另外提到欄位和值中間插了201行註解就完全沒有提醒，這個也一起處理：隔了超過200行還找不到值、後面又有比欄位深的內容時，列為要確認。

這兩個由Claude修改程式，也把審查報告的例子加進核心測試、瀏覽器測試和隨機測試，再重跑全部測試（結果在《TEST-REPORT-v1.1》）。

### 新手的步驟說明

修這兩個的時候，我又想到一件事：如果我是一個懵懵懂懂的新手，第一次打開看到五個面板，很可能不知所措，不知道該看哪裡、該點什麼、要注意什麼，也不知道哪些東西能給AI。所以我要求在最上面加「第一次用？照這5步做」，有點像之前Claude教我操作步驟的那種感覺：

- 每一步寫該看哪裡、該按什麼，還有要注意的地方。
- 最後一句直接講：可以貼給AI的，只有第3步「複製給AI」複製出來的內容；第1步的原文和第5步的還原結果都有隱私，不要貼給AI。
- 目前在哪一步，那一格會亮起來，寫「你在這一步」。
- 預設打開，熟悉之後可以收起來；不存任何設定。

這個也是直接寫在畫面上，沒有多加步驟或確認。

改完之後我自己用了最新版：最新版我自己用過，確實都有照我的需求改，我覺得現在應該所有人都會用了。畫面可能有點擁擠，第一次點進來可能會被大量文字嚇到一點，但至少每一步都有引導，應該不至於不知所措。比較擔心的是會不會有人沒耐心看完，這個要找真的新手試用才知道。

## 上傳前驗收又找到的（R09）

本來以為可以上傳了，上傳前我還是請Codex最後驗收一次，結果又抓到一個：JSON換行但沒有縮排的時候，`secrets`物件裡沒遮的值不會要求確認，畫面還顯示三項格式檢查都通過，可以直接複製。

```json
{"secrets":{
"password":"SYNTHETIC_COVERED",
"db":"SYNTHETIC_UNCHECKED"}}
```

原因是程式判斷大括號物件到哪裡結束時，也在看「下一行有沒有縮排」，沒縮排就以為物件已經結束，整個`secrets`物件根本沒被記下來檢查。單行或正常縮排的JSON都沒問題，所以之前的測試都沒抓到。

我要求修好才上傳。Claude把用大括號寫的物件改成只看括號配對、不看縮排；在行數上限內找不到結尾的，就當成沒檢查完，一定要確認。陣列裡的物件也一起改了。Codex報告裡的案例（短的、夾大量空行的、205個欄位後面接沒遮的值的）都加進核心測試和瀏覽器測試，單行和正常縮排的對照組也留著，確認行為沒變。

說真的，測試全部通過不代表沒有問題，這次又被證明了一次。
