## 一、ContextMask是什麼

**ContextMask是貼給AI除錯之前用的隱私遮罩工具：先找出程式碼、設定檔和錯誤訊息裡可能敏感的內容，讓使用者確認後換成代號；AI回覆之後，再把代號換回原本的內容。**

舉例來說，錯誤訊息和設定檔裡常常有這些東西：

```text
原文    File "C:\Users\wang\Desktop\hw5\main.py", line 42
        api_key = "sk-proj-EXAMPLE0000fake0000key0000"

遮罩後  File "C:\Users\USER_1\Desktop\PROJECT_1\main.py", line 42
        api_key = "sk-proj-KEY_1"
```

路徑只換掉使用者名稱那一段，斜線、檔名和行號都留著，AI還是看得懂錯誤發生在哪裡（`hw5`是自己加進自訂文字的專案名稱，所以也換成PROJECT_1）。AI回答時如果用到USER_1、KEY_1，把回答貼回來，就能換回原本的內容。

使用流程是五個步驟：

1. 貼上原文。姓名、學號這種規則猜不到的，可以自己加進自訂文字。
2. 掃描，逐筆決定要遮罩還是保留。
3. 產生結果，複製給AI（可以附上一段請AI保留代號的說明）。
4. 把AI的回覆貼回來。
5. 還原，看摘要確認哪些代號換回來了、哪些沒換。

- 形式：單一`index.html`，用原生HTML、CSS、JavaScript寫成，不用安裝，也不依賴外部套件、模型、後端或AI API。
- 使用方式：放在GitHub Pages上直接開，也可以下載後離線打開。
- 定位：專注在「AI程式除錯」這個情境，規則有限，但每一條都能說清楚、測得到。

## 二、開發動機與目標

我平常很常用AI，寫程式遇到錯誤或看不懂的地方，就會想把相關內容貼上去問。為了讓AI看懂問題，很容易直接複製整段錯誤訊息或設定檔。後來看到與AI使用和資料隱私相關的新聞，才開始注意到：這些看起來只是程式的文字，其實也可能帶出個人資訊。

例如，Python的錯誤訊息可能帶著`C:\Users\使用者名稱\...`；設定檔或`.env`裡可能有API金鑰、密碼；作業程式的註解也可能寫著姓名和學號。如果每次都自己一個個找、手動刪，很容易漏掉；但把整段內容刪掉，又可能讓AI少了判斷問題的線索。所以我想做一個工具，在送出前先幫忙找出需要注意的地方，讓我決定遮哪些、留哪些，收到AI回覆後還能換回來。

### 核心目標

1. 降低原文裡可辨識的敏感片段被送出去的風險。
2. 沒被替換的分隔符號、換行、縮排、檔名和錯誤位置都保留。
3. 同樣的原文用同一個代號，而且遮罩後直接還原要和原文一字不差。
4. 讓使用者知道哪些已經遮了、哪些是自己選擇保留、哪些是工具沒辦法保證的。

這個工具只能降低風險，不保證百分之百抓到，也不保證遮罩後AI一定除錯得比較好，這些要另外做實驗才能證明。

### 我的設計原則

> **把使用者當成什麼都不會的人來設計。**

這句有點嗆，原本是我半開玩笑講的，但我是真的這樣想：不是看不起使用者，而是不要假設使用者會仔細看說明、會點開收起來的東西。我自己當使用者操作v1.1的時候就發現，收起來的說明我其實不一定會點開，放在頁面最下面的東西也不一定會滑下去看。連我這個做工具的人都這樣，一般使用者更不用說。所以我用這個原則來判斷：

- 會影響隱私的提示，要放在不用點開就看得到的地方，而且就在要按的按鈕旁邊。
- 工具找不到的東西要直接講出來，不能讓使用者以為「檢查通過」就是全部遮好了。
- 第一次用的人要知道先看哪裡、按什麼，還有哪些東西可以給AI。
- 但正常的流程不要多加步驟和確認（D02、D03），不然操作會變麻煩，使用者就不想用了。

這句話是後來才講出來的，不過回頭看我前面每一個決定，其實都是同一個出發點：

- 題目：我自己就是會把錯誤訊息整段貼給AI的人，每次手動一個個找、一個個刪很容易漏，所以想做一個在送出前幫忙找的工具，而且收到回覆還能換回來，不用自己對照。
- D01短代號＋跳號：USER_1比一長串亂碼好讀，使用者和AI都看得懂；跳號的原因直接寫在結果旁邊，不用自己猜為什麼從USER_2開始。
- D02保留對照、細節收起來：我希望門檻低一點，不用一直找說明才知道在幹嘛，所以不改成一步一步的流程，只把畫面整理乾淨。
- D03沒遮完整時提醒加確認，不直接擋：我自己就是看到「檢查通過」會直接複製的人，所以風險一定要擺在眼前；但也不要一律擋下，讓使用者自己決定。
- D04敏感欄位底下的物件逐欄位遮再加確認：全部遮掉會少掉除錯線索，使用者問AI反而問不到重點；但`secrets`這種明顯的風險不能只寫在規格裡，要在畫面上提醒。
- A41再多引導：重要的東西不能收起來，最上面先講工具找得到和找不到什麼，複製前再提醒一次。
- 新手的步驟說明（F15）：我想像自己是懵懵懂懂的新手，第一次打開看到五個面板可能會不知所措，所以最上面直接寫5個步驟，該看哪裡、該按什麼、要注意什麼，哪些東西可以給AI。

## 三、問題、使用者與範圍

### 要解決的問題

- 路徑、traceback和日誌可能夾帶帳號名稱、電腦名稱、專案名稱和網路資訊。
- 設定值可能夾帶金鑰、密碼或連線資訊，自己檢查很容易漏看。
- 把路徑或整段內容刪掉，AI可能就少了判斷錯誤需要的線索。
- 要能還原的話，還要處理原文本來就有的代號、重複的值、重疊的範圍、AI改寫的代號和不認得的代號。

我查過的工具裡，已經有本機偵測和可以還原的設計，所以這些不是我首創的功能（見附錄C）。我想把重點放在程式除錯：保留有用的路徑結構、讓使用者知道為什麼被抓到，再把複製提問和貼回還原接成完整的流程。

### 目標使用者

資工學生和寫程式的人優先，但基本操作要讓一般AI使用者也看得懂。雖然使用者可能是資工學生或有相關知識的人，我還是希望門檻低一點，最好不用一直找說明才知道在做什麼。所以畫面用「為什麼被偵測」「遮罩／保留」「不認得的代號」這種白話，技術細節收起來，需要時再展開。

### 支援範圍

- 純文字的程式碼、Python和Node.js這類錯誤訊息、日誌。
- JSON、YAML、`.env`、命令列、Python、JavaScript裡常見的設定寫法（第六節列出實際認得哪些）。
- 使用者自己複製到AI服務，再把文字回覆貼回來；工具不會替使用者呼叫AI。

不在範圍內的：圖片、PDF、OCR、中文人名自動辨識、完整解析任意程式語言、跨好幾批對話的對照表、IPv6位址偵測、UNC路徑、私鑰區塊（會直接擋下複製）。處理成功也不代表遮罩後的程式還能直接執行。

## 四、使用流程與規則

第一次用的人照畫面最上面的「第一次用？照這5步做」操作就好（F15）。實際的流程是：

1. **貼上**：把原文貼進編輯框；需要的話加入自訂文字並選類型。
2. **掃描**：先記下原文裡本來就有的代號寫法（例如USER_1），再列出偵測到的內容。沒辦法完整處理的地方，會在第2步直接用提醒框列出來。
3. **審查**：每一筆都可以選遮罩或保留，也可以全部遮罩、全部保留，之後還能個別調整。
4. **產生**：依照選擇產生遮罩結果和這次用到的對照表，同時做三項檢查（見F08）。代號有跳號時，在結果下面說明原因。
5. **複製**：在複製按鈕上方看「已經完成」和「還要處理」的項目，以及「送出前再看一次」列的三件事。一般情況直接按複製；如果有沒遮完整的項目，要先勾選確認（見F13）。
6. **還原**：把AI回覆貼進來，只換這一批對照表裡的代號；還原結果下面會顯示摘要。
7. **清除**：用完按「清除全部」，原文、自訂文字、偵測結果、對照表、輸出和報告一起清掉。

一次只處理一批資料。只要改了原文、自訂文字或遮罩選擇，或是重新掃描、重新產生，舊的結果、對照表和確認全部作廢，畫面會提醒重新產生。同一批裡代號的編號會固定下來，同樣的內容不會換號。重新整理、離開頁面或清除之後，不會從任何儲存空間恢復。

## 五、功能需求

| 編號 | 功能 | 行為與完成條件 |
| --- | --- | --- |
| F01 | 原文與自訂文字輸入 | 原文、AI回覆各最多100,000字（以JavaScript字串長度計算，和輸入框一樣）；自訂文字最多50筆、每筆最多200字、不能換行。超過時明確拒絕，不截斷，也不產生部分結果。 |
| F02 | 本機掃描 | 依第六節的規則找出候選；同一段文字被好幾條規則抓到時合併成一筆。超過1,000筆時請使用者分段，不給部分結果。 |
| F03 | 自訂文字 | 完全一樣才算（分大小寫）；類型有姓名NAME、學號SID、專案名稱PROJECT、其他WORD。不開放自訂正規表達式。 |
| F04 | 逐筆審查 | 同樣的內容出現幾次就列幾筆，可以分開決定。每一筆都看得到種類、可信度、位置和遮罩／保留按鈕；判斷理由和保留的風險收在「判斷依據」裡，點開就看得到。可信度代表規則有多明確，不是準確率。 |
| F05 | 原文標記預覽 | 可以展開的標色預覽，點標記會跳到清單裡那一筆；清單每頁30筆。原文一律當純文字顯示。 |
| F06 | 保留結構 | 只換選到的範圍，其他字元一字不改。路徑只換使用者名稱那一段；跨好幾行的值每一行分開換，每行開頭的縮排和換行都不動。 |
| F07 | 代號與跳號 | 用USER_1這種短代號。原文本來就有的寫法先記下來，新代號跳過它們；同類型、同樣的原文共用同一個代號；對照表只放這次真的用到的代號。 |
| F08 | 檢查與阻擋 | 產生結果時做三項檢查：遮罩後直接還原要和原文一字不差；換行和每行開頭的縮排不變；原文是有效的JSON時（物件、陣列、字串、數字、true／false、null都算），遮罩後也要能解析。任何一項沒通過、代號會黏住旁邊的英數字，或原文有私鑰區塊，就不能複製，F13的確認也不能越過。檢查通過只代表這三項沒問題，不代表內容裡沒有其他敏感資訊。 |
| F09 | 複製與代號說明 | 可以選擇在開頭附上代號說明，說明只列這次實際用到的代號，不含原文和對照表。瀏覽器不讓自動複製時，幫使用者選好文字、請他按Ctrl＋C（Mac是⌘＋C）；工具不讀取剪貼簿。 |
| F10 | 精確還原 | 只換這一批對照表裡的完整代號，一次換完，換回來的內容不會再被當成代號。原文本來就有的代號、不認得的代號、看起來被改寫的代號都不換，分開列出來，不猜。 |
| F11 | 工作階段 | 規則見第四節最後一段。不使用localStorage、cookie這類儲存空間；清除不會清掉系統剪貼簿裡已經複製的內容，畫面上會說明。 |
| F12 | 範例與手機 | 可以載入虛構範例，已經有內容時先提醒會被取代。390px寬的手機也能走完整個流程，長的行在編輯框裡面捲動。 |
| F13 | 沒遮完整的項目（v1.1新增，決策D03、D04） | 工具認出是敏感內容、但沒辦法完整遮住時（情況見6.3，包含D04的敏感名稱底下的物件），在複製按鈕上方列出位置、風險和處理方式，複製先停用。使用者勾選「本次內容仍有未完整遮罩的敏感項目，我已查看並決定繼續複製」之後才能複製。這個確認預設不勾、不存起來、只算這一次產生的結果；勾選之後提醒照樣顯示，不會變成「都遮好了」。使用者補上自訂文字、讓那些範圍都被遮住之後，就不再算沒遮完整。 |
| F14 | 提示放在看得到的地方（v1.1新增，決策D02） | 代號跳號時，在遮罩結果下面直接說明原因，內容依實際分配算出來；還原結果下面直接顯示摘要；目前這一步的面板和主要按鈕會亮起來。一般說明、通過的檢查細節和完整還原報告可以收合；但會擋下複製、需要使用者處理的問題，一定直接顯示在相關按鈕附近，而且用文字標示，不只靠顏色。正常流程不多加確認或彈出視窗。我操作v1.1之後（A41）再加三點：最上面直接寫工具找得到、找不到什麼；複製按鈕上方列出「送出前再看一次」，按鈕可以直接打開完整內容、跳到自訂文字、打開完整的支援範圍；選了保留的那一筆，風險直接顯示。 |
| F15 | 第一次用的步驟說明（補充審查後新增） | 最上面直接列出5個步驟，每一步寫看哪裡、按什麼、要注意什麼；最後一句寫明可以貼給AI的只有第3步「複製給AI」複製出來的內容，第1步的原文和第5步的還原結果都有隱私，不要貼給AI。預設打開，看過可以收起來；目前在哪一步會跟著流程亮起來。不存任何設定，重新整理後又是打開的。 |

### 結構保留的界線

「保留結構」是指上面列出的那些文字不變，不代表所有語法、型別和程式行為都不變。代號長度和原文不一樣，同一行後面的欄位位置可能會移動。JSON裡的數字被換成代號會讓JSON失效，工具不會偷偷改成字串，而是擋下複製、說明怎麼處理（把那一筆改成保留，或先改原文）。

自訂文字不能換行，也不能包含引號、括號、斜線這些屬於程式結構的符號。自訂的英文片段如果藏在比較長的名稱裡（例如加了`secret`，原文卻是`prefixsecretsuffix`），換掉之後代號會黏住旁邊的字、沒辦法還原，所以這些地方不遮，改成提醒使用者把完整名稱也加進來（這種情況屬於F13）。

## 六、偵測與遮罩規則

以下例子都是虛構的教學資料。被抓到只代表符合某條規則，不代表資料是真的、帳號存在、金鑰有效或主機連得上。預設選項以降低風險為主，使用者都可以改。

### 6.1偵測的種類

| 類型 | 原文例子 | 遮罩後 | 判斷依據與範圍 | 預設 |
| --- | --- | --- | --- | --- |
| Windows／WSL使用者路徑 | `C:\Users\wang\Desktop\hw5\main.py` | `C:\Users\USER_1\Desktop\hw5\main.py` | `Users`後面到下一個路徑分隔符號或清楚的字串結尾；名稱有空白也整段算（例如`Demo User`）；支援`\`、`\\`、`/`和`/mnt/c/Users/`。看不出名稱到哪裡結束時不猜，改成提醒（F13） | 遮罩，可信度高 |
| Linux／macOS使用者路徑 | `/home/wang/app/main.py` | `/home/USER_1/app/main.py` | `/home/`、`/Users/`後面那一段；網址裡的`/home/`不算 | 遮罩，可信度高 |
| 電腦名稱 | `DESKTOP-DEMO123` | `HOST_1` | `DESKTOP-`、`LAPTOP-`加4到15個英數字；認不出其他自訂的主機名稱 | 遮罩，可信度中 |
| 已知開頭的金鑰 | `sk-proj-EXAMPLE0000fake0000key0000` | `sk-proj-KEY_1` | 附錄B列出的開頭、字元和長度；後面整段遮完，不留片段；不驗證金鑰是否有效 | 遮罩，可信度高 |
| JWT登入權杖 | 三段用`.`分開的Base64URL文字 | `TOKEN_1` | 三段、而且前兩段解開都是JSON物件才算；不驗證簽章和有效期限，不包含五段的JWE | 遮罩，可信度中 |
| 資料庫連線字串 | `postgres://admin:demo_pass@db.example.invalid:5432/demo` | `postgres://admin:SECRET_1@HOST_2:5432/demo` | postgres、postgresql、mysql、mariadb、mongodb（含`+srv`這類寫法）；只換密碼和不是localhost的主機，協定、帳號、埠和資料庫名稱留著。看不懂格式時整段遮住並提醒 | 遮罩；密碼可信度高，主機中，格式特殊時標低 |
| 敏感欄位的值 | `password="demo_pass"` | `password="SECRET_1"` | password、secret、token、api_key、access_token、authorization這類欄位後面的值；認得的寫法見6.2 | 遮罩，可信度中 |
| 電子郵件 | `demo.student@example.invalid` | `EMAIL_1` | 常見的英數帳號加網域，網域一起換掉；不保證所有RFC或Unicode地址 | 遮罩，可信度中 |
| 台灣身分證字號 | `A123456789` | `TWID_1` | 英文字母＋1或2＋8碼數字，依官方加權方式驗證檢查碼；不包含所有居留證格式 | 檢查碼正確為可信度高、不正確為低，兩種都預設遮罩 |
| 台灣手機號碼 | `0912-345-678` | `PHONE_1` | 09開頭10碼，或+886開頭的寫法，可以用空白或連字號分段 | 遮罩，可信度中 |
| IPv4位址 | `203.0.113.5`、`192.168.1.10` | `IP_1`、保留 | 四段0到255；內部網路（10.、172.16～31.、192.168.）和本機（127.）預設保留，其他預設遮罩 | 全部列出，附分類和風險 |
| 自訂文字 | `王小明`、`SYNTHETIC_SID_001`、`hw5` | `NAME_1`、`SID_1`、`PROJECT_1` | 使用者自己選類型，完全一樣才算 | 遮罩，標示「你指定的」 |

### 6.2敏感欄位的值：認得哪些寫法

欄位名稱會先統一成小寫加底線（`apiKey`→`api_key`），結尾是敏感字就算，例如`DB_PASSWORD`、`clientSecret`、`GITHUB_TOKEN`；`passwords`、`api_keys`這種複數也算。`tokens`只有整個名稱就是它才算，因為`max_tokens`、`total_tokens`是用量的數字。

| 寫法 | 例子 | 怎麼遮 |
| --- | --- | --- |
| 引號字串 | `password = "abc"`、`"apiKey": "abc"`、`"Password ": "abc"` | 遮引號裡面的全部內容；認得`\"`這種跳脫；欄位名稱的引號裡多了空白也算 |
| 型別標註、中括號、宣告 | `password: str = "abc"`、`config["password"] = "abc"`、`config[ "password" ] = "abc"`、`var password string = "abc"` | 遮等號後面的值；中括號裡有空白也算 |
| YAML、SQL的兩個單引號 | `password: 'demo''SUFFIX'` | `''`算同一個字串裡的單引號，整段遮完 |
| Python三引號 | `password = """abc"""` | 同一行的完整遮；跨行的每一行分開遮，縮排不動 |
| JavaScript、Go的反引號 | `` token = `abc` `` | 同上，可以跨行 |
| 接在一起的字串 | `password = "abc" "def"`、`"abc" + "def"`、`("abc", "def")` | 每一段都遮；括號裡的字串可以分好幾行寫 |
| 字串裡的JSON | `"{\"password\": \"abc\"}"` | 遮裡面那層字串的值，陣列也一樣 |
| 欄位名稱在字串裡 | `log("password=%s", "abc")`、`"SELECT … WHERE password = 'abc'"`、`print("password:", "abc")`、`'password=abc&user=a'` | 格式化字串遮對應的參數（同一個字串有好幾個佔位也對得到，參數換行寫也對得到）；字串裡用另一種引號包起來的值也遮；表單格式遮到下一個`&名稱=`為止；`"Enter password:"`這種後面沒有值的提示文字不遮 |
| 和寫死的字串比對 | `if password == "abc"`、`token === 'abc'` | 遮比對的字串；`typeof token === "string"`這種型別檢查不算 |
| 讀設定、寫設定的呼叫 | `os.getenv("DB_PASSWORD", "abc")`、`process.env.TOKEN \|\| "abc"`、`define('DB_PASSWORD', 'abc')`、`setItem('token', 'abc')` | 遮寫在程式裡的值，呼叫本身不遮；第一個參數要是敏感欄位的名稱才算。值寫在下一行也遮；字串沒貼完整時遮第一行，列為要確認 |
| 陣列 | `"token": ["a", "b"]`、`token: [a, b]` | 每個元素都遮（沒引號的數字和true／false這類不遮）；陣列裡的物件跳過，物件裡的欄位另外檢查 |
| 命令列和`.env`的`KEY=值` | `DB_PASSWORD=abc`、`docker run -e DB_PASSWORD=abc img` | 遮到空白為止（`a\ b`這種跳脫的空白算在值裡）；結尾的分號當成命令分隔，不遮。值本身以`=`、`>`開頭（`DB_PASSWORD==abc`）也照樣遮。行首的大寫環境變數後面還有其他文字時，列為要確認（見6.3） |
| 整行的值（YAML、INI） | `password: abc,;`、`[db]`底下的`password=abc def` | 遮到行尾或`#`註解為止。行尾的逗號、分號也是值的一部分，一起遮；值看起來是程式的變數、數字或函式呼叫時，逗號、分號才當成程式的標點留著。行首的小寫欄位（INI、`.properties`）照整行算，大寫的環境變數照命令列算 |
| 大括號開頭的值 | `password: {SSHA}abc`、`password = {abc}` | 當成值本身整段遮；`{"user": …}`這種真的物件，裡面的欄位另外檢查 |
| YAML多行值 | `password: \|`、`>-`、`\|2`、`!vault \|` | 下面縮排比較深的每一行都遮，行尾的逗號、分號一起遮 |
| YAML的值延續到下一行 | `password: abc`下一行縮排更深、`"password": abc`下一行縮排更深 | 延續的那幾行也遮；欄位名稱加了引號也一樣 |
| 值寫在下一行 | `{"password":`換行`"abc"}`、`password:`換行`  - abc` | JSON、JavaScript、YAML都可以把值寫在下一行：引號字串、陣列、YAML清單、YAML純文字都會遮；下一行是另一個欄位或巢狀物件時，不當成值 |
| Authorization標頭 | `Authorization: Bearer abc`、`"Bearer " + "abc"` | 只遮`Bearer`後面的值；`$TOKEN`、`<token>`這種佔位不遮 |

不會被遮的值：`None`、`null`、`true`、`false`和型別名稱；`<your-password>`、`{{ secret }}`、`****`這種佔位文字；`password = getpass()`、`const token = getToken(user)`、`tokens[0]`這種程式呼叫和取值（呼叫裡面的欄位、讀設定的預設值和`||`後面的預設值照樣檢查）。看起來像變數或參照的值（`$PW`、`config.password`）也可能是真的密碼，所以照樣遮，但標成可信度低，讓使用者確認。

認不出來的寫法：物件裡的欄位只看各自的名稱，所以`secrets:`底下的`db: abc`，因為`db`不是敏感字，不會自動遮，但會照D04列為要確認（見6.3）；把密碼寫成YAML的欄位名稱，或欄位名稱用`\u0077`這種跳脫寫的，也認不出來。JSON的冒號單獨寫在一行（`"password"`換行`:`換行`"值"`）時，會把冒號誤當成值遮掉，值本身沒遮；這時JSON會被破壞，複製會被擋下，把冒號移回欄位名稱那一行再掃描就好。`password = abc #def`的`#def`照YAML和`.env`的規則當成註解。這些情況請用自訂文字。

跨行的值（三引號、反引號、陣列，以及寫在下一行的YAML清單和內容）最多往下看200行；YAML用`|`、`>`標記的多行值沒有行數限制。

### 6.3沒辦法完整處理時怎麼辦

工具認出來、但沒辦法完整處理的地方，依照影響分成三種，畫面上都用文字標出來：

| 情況 | 工具怎麼做 | 分類 |
| --- | --- | --- |
| 一般引號的字串找不到結尾 | 先遮到這一行結尾；值可能延續到下一行 | 沒遮完整，要確認（F13） |
| 三引號、反引號的字串找不到結尾，或超過200行 | 只遮第一行 | 沒遮完整，要確認 |
| 陣列找不到結尾 | 遮找得到的項目 | 沒遮完整，要確認 |
| 寫在下一行的YAML清單或內容超過200行 | 遮前面200行 | 沒遮完整，要確認 |
| 路徑看不出使用者名稱到哪裡為止 | 不猜，不遮 | 沒遮完整，要確認；把完整名稱加進自訂文字就解除 |
| 行首的大寫環境變數後面還有其他文字（`PGPASSWORD=abc psql -h db`） | 照命令列的規則遮到空白為止，後面的文字不遮 | 沒遮完整，要確認；後面那段也是值的話，加進自訂文字就解除 |
| 敏感名稱底下是物件（`secrets:`底下的`db: abc`、`credentials`裡的`user`），裡面有沒遮的值 | 子欄位照各自的名稱遮（`password`照遮），其他的值不遮。引號裡的字串不管內容像什麼（中文、符號、`"false"`、`"demo()"`）都算值 | 沒遮完整，要確認（D04）；那些值都加進自訂文字就解除；子欄位全部遮到時不用確認 |
| 敏感名稱底下的物件超過200行，或大括號找不到結尾 | 只檢查看得到的部分。用大括號寫的物件照括號配對判斷範圍，不看縮排（JSON換行但沒縮排也一樣） | 沒遮完整，要確認；後面沒檢查到，不能用自訂文字解除，要分段貼上或確認後複製 |
| 欄位和值中間隔了超過200行的空行或註解 | 不再往下找值 | 沒遮完整，要確認；把中間刪短再掃描，或確認後複製 |
| 自訂文字藏在比較長的名稱裡 | 那些地方不遮 | 沒遮完整，要確認；把完整名稱也加進自訂文字就解除 |
| 私鑰區塊（BEGIN／END PRIVATE KEY） | 不遮，擋下複製 | 不能複製，請先從原文刪掉 |
| 遮罩後還原不回原文、換行縮排變了、原本有效的JSON失效、代號會黏住旁邊的字 | 擋下複製並說明原因 | 不能複製，確認也不能越過 |
| 連線字串格式看不懂、密碼裡有沒編碼的`/`或`@`、IPv6主機、好幾個主機 | 已經保守地遮了，提醒使用者看一下範圍 | 提醒，不影響複製 |

### 6.4重要取捨

- `wang`出現在四種寫法的路徑裡，共用同一個USER代號，因為分隔符號都留著；`Wang`和`wang`分別配號，不然還原時不知道要換回哪一種大小寫。
- 同樣的文字用同一個代號，是為了讓AI看懂重複出現的東西，不代表工具能確認不同系統裡的同名帳號是同一個人。
- 保留金鑰開頭（例如`sk-proj-`）會透露金鑰種類，但能讓AI知道是哪一種金鑰。只有附錄B指定、不會和代號黏在一起的開頭才保留，其他整串換掉。同一把金鑰同時被「已知開頭」和「敏感欄位」抓到時，只處理一次。
- 連線字串裡的帳號、資料庫名稱和協定留著，還是一種線索。不是localhost的主機都當成要遮的候選，不靠名稱判斷是內網還是外網；IP主機照IPv4的規則處理。
- 內部網路和本機的IP預設保留，但「預設保留」不代表沒有隱私風險，清單裡一樣列出來，可以改成遮罩。
- 私鑰是多行的整塊內容，換成一個代號會改變行數，這一版不處理，遇到就擋下複製。
- 一般引號的字串要在同一行結束。有些格式允許引號字串跨行，但這種時候很難確定結尾在哪，誤判的話反而可能把下一個欄位的值漏掉，所以這一版只遮第一行，並列為沒遮完整。
- YAML裡`password: #abc`的`#`後面會被當成註解。如果下一行有縮排更深的值，就遮下一行；沒有的話，保險起見把`#abc`這段也遮住，標成可信度低，確定是註解可以改成保留。
- `DB_PASSWORD=abc npm start`空白後面是要執行的命令；可是`.env`裡沒加引號、本來就有空白的值，空白後面那段也是密碼。兩種寫法看不出差別，所以行首的大寫環境變數遮到空白為止，後面還有文字時照F13列為要確認，讓使用者決定。同一行接著的是另一個`KEY=值`、`&&`、`|`這類命令符號時，不用確認。
- 物件裡的欄位只看各自的名稱，這是v1.0就有的規則（A15）：`{"credentials": [{"user": "demo", "password": "x1"}]}`只遮`x1`，`demo`留著讓AI看得懂。代價是`secrets:`底下的`db: abc`不會自動遮，所以我決定（D04）規則先不改，改成把這種物件列為要確認，讓使用者自己看過；「依父層判斷所有子欄位要怎麼遮」列在10.4。

## 七、代號、撞名、映射與還原

我選的是**短英文代號＋先掃描原文、跳過已經有的編號**，不用v0原型那種很長的隨機前綴（例如`__CM_隨機碼_USER_1__`）。短代號比較容易閱讀，但也可能剛好跟原文撞名或被AI改寫，所以搭配「先記下原文已有的寫法」和「只還原這一批對照表裡的代號」來處理，而不是把代號短當成安全保證。

### 7.1代號怎麼分配

1. 先找出原文裡符合代號樣子的文字，類型包含USER、HOST、KEY、TOKEN、SECRET、EMAIL、TWID、PHONE、IP、NAME、SID、PROJECT、WORD。藏在比較長的名稱裡的（例如`OTHER_USER_1`裡的`USER_1`）也算，保守一點。
2. 每種類型從1開始編號，跳過原文已有的和這一批已經分配過的。原文有USER_1、USER_2的話，新的從USER_3開始。
3. 「類型＋原文片段」相同的共用一個代號，不同類型不合併。
4. 同一批裡編號固定：某一筆先拿到IP_1，之後改成保留再改回來，還是IP_1；IP_1在這一批已經分給別的內容時，新的內容不會拿到IP_1。
5. 代號跳號時，在遮罩結果下面直接說明原因，例如「原文本來就有USER_1，所以使用者名稱的新代號跳過這個編號，這次用的是USER_2。還原時只換這次的代號，原文的USER_1不會被換掉。」這段說明是照實際分配的結果算出來的，原因有兩種：原文本來就有，或是這一批之前分配給了現在選擇保留的內容。

### 7.2還原的邊界

- 只認完整的代號：USER_1不會對到USER_10，也不會去改`OTHER_USER_1`這種比較長的名稱。
- 只換這一批對照表裡的代號，一次換完；換回來的原文裡如果剛好有代號字樣，不會再被換一次。
- 金鑰保留開頭的，對照表記的是後面那段；整串換掉的，記的是整串。兩種都能直接還原成原文。
- AI如果改了路徑、JSON或程式字串的寫法，就算代號能換回來，也不保證跳脫語法或程式行為正確。

### 7.3還原摘要與完整報告

還原結果下面直接顯示摘要，不同情況分開說，不會全部叫做「還原失敗」：

| 情況 | 例子 | 摘要怎麼寫 |
| --- | --- | --- |
| 這一批的代號 | 回覆裡的USER_2 | 「換回N處」，列出每個代號換了幾次；畫面上換回來的地方有底線 |
| 原文本來就有 | 原文的USER_1 | 「沒有換：原文本來就有」，說明這是原文自己的內容，不是這次的代號 |
| 不認得的代號 | 回覆裡的USER_9 | 「要確認：不認得的代號」，保持原樣，不猜原本是什麼 |
| 看起來被改寫 | `user_2`、`USER-2`、`使用者2` | 「要確認：看起來被改寫過」，提示可能是哪個代號，但不自動換 |
| 這次沒出現的代號 | 回覆沒用到PROJECT_1 | 放在完整報告裡，可能只是AI沒用到，不一定有問題 |

完整報告預設收起來，點開可以看到每一種情況的清單。

### 7.4給AI的代號說明

只列這次實際用到的代號，例如：

> 以下內容中的USER_1、KEY_1、EMAIL_1是隱私保護代號，代表被隱藏的原始資料。回答時請原樣保留這些代號（拼字、大小寫和編號都不要改），不要翻譯、重新命名，也不要猜測原始內容；代號出現在路徑或金鑰開頭後面時，也請保留周圍的格式。

說明和正文分開組裝，檢查只針對正文。這次沒有替換任何內容時，不附說明。

## 八、介面設計

v1.0做完後我自己操作了一次，覺得能自己決定遮哪些內容這點不錯，但畫面有點雜，提示可能漏看，尤其是為什麼從USER_2開始、還原為什麼有些沒換這些地方。當時想過兩種改法：保留原文和結果對照、把細節收起來，或是改成一步一步引導。兩個都不錯，我比較偏向第一個，因為我希望操作不要太麻煩，也不要增加太多限制。畫面盡量乾淨，但提示要讓人看得到、記得住。

下面這些排法是我照這個方向定的。v1.1做完之後，我又用第二節的設計原則重新想了一次哪些要直接看得到、哪些可以收起來，判斷的方式就是「使用者沒點開也不會漏掉重要的事」：

- 版面：1200px以上分三欄，由左到右是原文、審查清單、遮罩結果，原文和結果可以左右對照；768到1199px時原文和結果並排，審查清單在下面佔一整列；更窄的螢幕照步驟排成一欄。下面是貼回回覆和還原結果。
- 目前步驟：目前這一步的面板外框和步驟編號會亮起來，主要按鈕只有這一步是實心的，其他步驟的按鈕變成外框樣式，還是可以按。
- 收起來的東西：每一筆的判斷依據、通過的檢查細節、完整還原報告、要複製的完整內容、完整的支援範圍清單。
- 一定直接看得到的東西：最上面的「第一次用？照這5步做」（預設打開，看過可以收起來）和「工具找得到什麼、找不到什麼」、第2步的提醒框、選了保留的那一筆的風險、遮罩結果下面的跳號原因、複製按鈕上方的「已經完成」「還要處理」和「送出前再看一次」、沒遮完整時的確認框、還原結果下面的摘要。
- 標示方式：每一種狀態都有文字和符號（✓已完成、✕不能複製、!要確認、i提醒、－保留），不只靠顏色。
- 深色工作台風格，原文和結果用等寬字體，不載入外部字型；代號用黃色膠帶樣式標出來。
- 按鈕和輸入框都有鍵盤焦點和標籤；手機上主要按鈕至少44px高；長的行只在編輯框裡面橫向捲動。
- 沒有找到任何內容時，畫面寫「沒有找到符合規則的內容。這不代表沒有敏感資訊，複製前請自己再看一遍。」

我覺得可以參考其他工具怎麼排，Codex整理了兩個公開頁面：[KilaHub個資遮罩工具](https://kilahub.com/tools/data-anonymizer/)把輸入和結果並排、規則設定集中在一區，[Preserve示範頁](https://thirtysix.github.io/Preserve/)把操作、偵測標記和輸出分成區塊。這次只參考資訊怎麼分組，沒有使用它們的程式碼。

v1.1做好之後我又自己操作了一次（A41）。跳號說明和還原摘要比較好懂了，操作也還行，就算是入門的人應該也會用。不過我發現，「支援哪些寫法、有哪些限制」放在頁面最下面還要點開，我自己當使用者都不一定會滑下去看；「查看要複製的完整內容」和其他收起來的地方也一樣，比較重要的資訊使用者不一定會點開或特別注意。我覺得要再多引導一下，讓使用者能更確定、更安心地把內容複製給AI，所以決定再改三個地方。這幾個改動不大，我提出調整要求，畫面和樣式主要由AI修改：

- 最上面直接寫工具找得到什麼、找不到什麼（要自己加進自訂文字的那些），完整清單才收起來。
- 複製按鈕上方加「送出前再看一次」，把三件事直接寫出來，每一件都有按鈕：打開要複製的完整內容、跳到自訂文字、打開完整的支援範圍。
- 選了保留的那一筆，「如果保留」的風險直接顯示，不用展開。

這些都是用文字直接寫出來，沒有多加步驟或確認，跟D02「操作不要太麻煩」的方向一致。

後來我又想到一件事：如果我是一個懵懵懂懂的新手，第一次打開看到五個面板，很可能不知所措，不知道要先看哪裡、該按什麼，也不知道哪些東西可以給AI。所以我要求在最上面加「第一次用？照這5步做」，感覺就像有人在旁邊教你操作，每一步寫該看哪裡、該按什麼、要注意什麼，最後一句直接講只有第3步複製出來的內容可以貼給AI。這個說明預設打開，熟悉之後可以收起來，目前在哪一步也會跟著亮起來（F15）。

最新版我自己用過，確實都有照我的需求改，我覺得現在應該所有人都會用了。畫面可能有點擁擠，第一次點進來可能會被大量文字嚇到一點，但至少每一步都有引導，應該不至於不知所措。比較擔心的是會不會有人沒耐心看完，這個要找真的新手試用才知道。

## 九、隱私、資安、效能與部署

### 9.1本機處理的邊界

不使用後端或雲端AI，不載入外部的JavaScript、字型、圖片、CDN、分析工具或模型。原文、自訂文字和對照表只放在這個分頁的記憶體裡，不使用localStorage、sessionStorage、IndexedDB、cookie、Service Worker，也不下載檔案。

網頁用meta標籤設定CSP（內容安全政策）：default-src、connect-src、img-src、font-src、object-src、frame-src、worker-src、base-uri、form-action都是none，script-src和style-src只允許檔案裡那一段程式和樣式的SHA-256雜湊，也要求Trusted Types。不使用unsafe-inline、eval、動態載入或寫在HTML標籤上的事件。

- 改了`<script>`或`<style>`裡的內容，雜湊就要重新計算（開發檔案裡的`build.cjs`和`tools/update-csp.cjs`會處理）。沒有重算時，`<script>`對不上，瀏覽器會擋掉整段程式，畫面停在「網頁程式沒有啟動」；`<style>`對不上，只有樣式被擋，功能還在但排版會跑掉。只改這兩段以外的HTML文字，不影響雜湊。
- 這個網頁不會把貼上的內容傳出去，CSP也擋住了網頁對外連線。但CSP管不到瀏覽器擴充功能、輸入法、剪貼簿工具、作業系統這些網頁以外的程式，也管不到使用者複製出去之後的內容；meta標籤設定的CSP也不能取代伺服器回應標頭的所有保護。
- 清除是把網頁裡的資料清掉，不保證覆寫實體記憶體，也不會清掉系統剪貼簿。

### 9.2輸入與顯示

- 所有文字欄位都設`spellcheck=false`、`autocomplete=off`、`autocorrect=off`、`autocapitalize=off`。這是給瀏覽器的提示，不能保證控制外部服務。
- 原文、範例、回覆和理由只用`textarea.value`、`textContent`或文字節點顯示，不把使用者的文字組成HTML、網址、事件或可以執行的程式。整頁標示不要翻譯，避免內容被送去翻譯服務。
- 只在使用者按複製時寫入剪貼簿，不讀取剪貼簿。還原結果又含有原始資料，畫面會提醒。
- 不把使用者的資料寫進console或任何紀錄。

### 9.3效能

輸入長度和候選數量都有上限，也不開放自訂正規表達式。規則用區間記錄、一次組裝替換，避免一直重複掃描整段原文；長串同一個字元、大量重複的欄位、沒有結尾的括號這類特殊輸入都另外測過。目標是接近100,000字的內容在桌機上2秒內完成掃描和遮罩。實際測量的環境和數字記在《TEST-REPORT-v1.1》，那是在Node.js裡量的核心時間，不代表手機上的畫面速度。

### 9.4部署

GitHub Pages第一次打開需要網路，載入之後的處理都在本機。下載`index.html`之後，斷網直接打開也能用。

### 10.2我做的設計決定

**D01代號：短代號＋跳號。** 我選USER_1這種短代號，主要就是包括我在內的使用者可以更容易讀。只是程式裡本來就可能有USER_1，所以我決定先找出原文已有的代號，新的跳過它，從USER_2開始。還原只換這次發出去、有對照資料的代號，原本的USER_1不動。像USER_9這種對照表沒有的，就列出來，不要自己猜原本是什麼。v1.1把跳號的原因直接顯示在結果旁邊（F14）。

**D02介面：保留對照，細節收起來。** 原因寫在第八節。我不想整個重做，主要是讓使用者更快上手理解，所以只做小修：提示換位置、細節收起來、標出目前步驟，這幾個由我提出要求，再由AI修改程式。另外我也希望狀態不要只靠顏色分辨，所以每一種都加上文字和符號；手機上主要按鈕要夠大、好按；什麼都沒找到時也要提醒「這不代表沒有敏感資訊」，免得使用者以為這樣就沒事了。

**D03沒遮完整的敏感欄位：醒目提醒，確認後可以複製。** 討論到密碼還在、畫面檢查卻通過的情況，我確實會直接複製給AI，所以提示需要再清楚一點，要讓使用者知道哪裡有問題。AI原本比較建議遇到沒處理完整的敏感欄位就先擋複製，我最後選的是「醒目提示風險，使用者確認後仍可複製」，這也跟前面希望不要太多限制的方向一致。不過已經找到的漏遮還是要修，不能只是多放一句提醒就算好了；確認也只算這一次的結果。至於還原不回來、原本有效的JSON被弄壞這種，還是照規格擋下，不能用確認跳過。正常沒有問題的流程，就不要再加一次確認。

**D04敏感欄位底下的物件：保留逐欄位遮罩，加上D03的確認。** 例如`secrets:`底下的`db: abc`，`db`不是敏感字，所以不會遮。我決定這版保留逐欄位遮罩，再對敏感欄位底下的物件加上D03的確認，這樣比較符合希望保留除錯線索、操作又不要限制太多的方向。我會這樣選有三個理由：

- `credentials`裡可能同時有帳號、密碼和設定值，全部遮掉會少掉除錯線索。
- `secrets`已經是明確的風險線索，應該在畫面上提醒，不能只寫進規格的限制。
- 這版先把提示和確認做好，範圍比較能控制；「依父層判斷所有子欄位要怎麼遮」之後再做。

所以`password`照原本的規則遮；`db: abc`的用途看不出來，就在複製按鈕上方醒目提示：這段物件只依子欄位名稱偵測，其他值可能還有敏感資訊，請檢查，需要遮的值可以加進自訂文字。使用者可以補遮罩，也可以看過之後勾選確認再複製，確認一樣只算這一次的結果，內容改了就失效。畫面上的提示照我寫的那句改；要判斷物件範圍到哪裡、哪些子欄位已經遮到，這部分的程式比較複雜，請Claude照這個決定寫。

在這之前，我也決定了題目、先專攻程式除錯，以及判斷每一輪AI的建議要不要採用。v1.1這一輪，我決定先修密碼漏遮、YAML、Python三引號和JSON檢查的問題，測試程式不能寫死某一台電腦的路徑，介面只做小修，而且沒測到的項目要直接寫沒測到。v1.1做完之後，我參與基本操作，另外請Codex審查並找出漏遮；我要求修完再公開，不要帶著已知的漏遮上傳。補充審查又找到R07、R08之後，我的要求是：已經有`secrets`這種風險線索，物件裡沒遮的字串就要確認，不能因為內容看起來像中文、符號或程式就略過；沒檢查完的長物件也不能當成已經處理好。另外我決定加上新手的步驟說明（F15），讓第一次用的人也知道每一步要做什麼。

## 附錄A：資料結構與處理流程

### A.1資料結構

```text
Candidate {
  id, start, end, type, raw, priority, confidence,
  selected, reasons[], risk, overlaps[]
}
Warning {
  offset, line, kind, level（block／confirm／notice）,
  message, risk, fix, ranges[]
}
Batch {
  source, candidates[], warnings[],
  reserved: Set（原文已有的代號寫法）,
  allocations: Map（類型＋原文片段 → 代號）,
  assigned: Set, nextNumber
}
MaskResult {
  body, replacements[], activeMap: Map（代號 → 原文片段）, emitted[],
  checks { roundTrip, structure, json }, problems[], blockers[], copyAllowed,
  incomplete[]（沒遮完整、要確認的Warning）, notices[],
  skipped[]（每種類型跳過了哪些編號、原因）
}
RestoreReport {
  text, segments[], restored[], reservedSeen[], unknown[], absent[], suspected[]
}
```

`start`、`end`是JavaScript字串的半開區間`[start, end)`，`raw`一定等於`source.slice(start, end)`。位置提示從原始字串算出來，不在正文插入行號。`allocations`可以替目前選擇保留的內容保留編號，讓同一批的代號穩定；`activeMap`只放這次輸出真正用到的代號。原文已有的代號清單不是還原用的對照表。

能不能複製由兩件事決定：`copyAllowed`（硬性檢查都通過）和確認狀態。`copyAllowed`是false時一定不能複製；`incomplete`不是空的時，要使用者確認「這一次的結果」才能複製。確認狀態只放在畫面的變數裡，結果一清掉就跟著歸零。

### A.2掃描和遮罩

1. 檢查長度和自訂文字限制。
2. 先記下原文已有的代號寫法，再用第六節的規則和自訂文字找出候選；沒辦法完整處理的地方記成Warning，標上分類。
3. 同一段被好幾條規則抓到時留下優先順序最高的類型、合併理由；只要有一條建議遮罩就預設遮罩。
4. 使用者審查每一筆。
5. 選到的範圍如果重疊或緊貼，合併成一組；有一筆剛好蓋住整組就用它的類型，只是部分交叉的合併成WORD。合併後跨過引號或換行、或代號會黏住旁邊的英數字，就擋下來，請使用者調整。
6. 每一組只換一次，從左到右組出正文，不用連鎖取代。
7. 做三項檢查（F08），算出還沒處理完整的項目和跳號原因。
8. 檢查通過後，再組合代號說明和正文。

### A.3還原

確認有這一批的結果 → 檢查回覆長度 → 一次找出完整的代號 → 這一批的代號換回原文並計次 → 原文已有的和不認得的保持不動 → 算出這次沒出現的代號和看起來被改寫的寫法 → 用純文字顯示結果和摘要。

還原用的是這一批的`activeMap`，不從類型、編號或上下文猜原值。只有「遮罩後直接還原要和原文一樣」是強制檢查；AI的回覆可能改了跳脫、引號、檔名或邏輯，還原之後不保證JSON有效或程式能執行。

| 可逆 | 遮罩後直接還原，要和收到的原文一字不差 | AI改寫之後一定能還原；原始檔案的位元組完全不變 |

| 沒遮完整 | 列出工具認出來、但沒辦法完整遮住的地方 | 沒列出來就代表沒有敏感資訊 |
| 剩下的線索 | 提醒使用者自己保留的項目，以及檔名、資料夾、註解、網域這類線索 | 已經找出所有能認出你的資訊 |

## 附錄D：規格從v1.2到v1.3改了什麼

| v1.2的寫法 | v1.3的改法 | 原因 |
| --- | --- | --- |
| 敏感欄位只說「單行值」 | 6.2逐項列出認得的寫法，包含值寫在下一行、YAML多行、三引號、反引號、接在一起的字串、字串裡的JSON | Codex測試時發現JSON值換行、YAML的`''`、多行值行尾的`,;`、Python三引號會漏遮（R01～R03），修好之後把實際支援的範圍寫清楚 |

| 6.2沒有列出程式裡的其他寫法 | 加上型別標註、讀設定和寫設定的呼叫、欄位名稱在字串裡、和寫死的字串比對、命令列的特殊寫法、大括號開頭的值，也寫出認不出來的寫法；6.3加上命令列後面還有文字的情況 | 修R01～R04時另外做的漏遮審查，找到這些寫法會漏遮或誤遮，修好之後把範圍寫清楚 |
| 無閉合引號等「須有警告」 | 6.3把沒辦法完整處理的情況分成「要確認」「不能複製」「提醒」三種，F13規定確認怎麼運作 | 我決定沒遮完整時醒目提醒、確認後可以複製（D03），硬性阻擋維持不變 |
